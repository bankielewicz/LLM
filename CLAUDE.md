# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository holds

1. **The LLM Foundations learner interface**: a static app in `dist/` that presents a 13-lesson course with simulations, recorded runs, a notebook and a capstone. It is deployed as-is, with no build step, to a ChatGPT Site (`.openai/hosting.json` names `dist` as the static directory). It does not run training.
2. **`docs/specs/intermediate-v1/`**: the sealed implementation specification for the next buildout, revision 1.1, approved by the owner on 2026-09-30. It describes a 24-module application plus a same-origin local Python companion that does real tokenizer, tiny-model and adapter training. **None of it is implemented yet**, and every acceptance case is `NOT_RUN`.

The course content's canonical source is a separate package, `llm-foundations-v2`, which is not in this repo. `course/` and `dist/course/` are byte-identical copies of it.

## Commands

Run everything from the repo root. The site needs no npm or pip packages.

```bash
python3 -m http.server 4173 --directory dist          # preview at http://localhost:4173
node --test qa/core.test.mjs qa/import-regressions.test.mjs
node --test --test-name-pattern="Shifted targets" qa/core.test.mjs   # a single test
node qa/templates.mjs        # renders every page template in node:vm; writes qa/template-output.json (gitignored)
python3 -X utf8 qa/audit.py  # run after templates.mjs: IDs/labels/links, palette contrast, source and ZIP hashes
```

`qa/audit.py` and `scripts/sync_course.py` look for the canonical package at `../llm-foundations-v2`, a sibling of the repo root. If it isn't there, the audit fails with `FileNotFoundError` even though nothing is wrong with the site. `sync_course.py` also accepts the package path as an argument.

**Course labs (PyTorch).** These run from the canonical package's root, not from this repo:
- tests: `python -m unittest discover -s labs -p test_lab.py -v`
- CLI: `python labs/lab.py tokenize|train|evaluate|generate …`; `course/START_HERE.md` has the full command lines.
- dependency: `course/requirements.txt` pins `torch==2.11.0`.

**Specification checks.** Run these under Python 3.12 with `jsonschema` and `referencing` installed. Each `--report` path is resolved relative to the **spec root**, so write `reviews/<name>`, never `docs/specs/...`. Every report name must be new.

```bash
python3 docs/specs/intermediate-v1/tools/check_spec.py --report reviews/<new>.json --check-index
python3 docs/specs/intermediate-v1/tools/check_contract_edges.py --strict --report reviews/<new>.md
python3 docs/specs/intermediate-v1/tools/check_fixture_oracles.py --report reviews/<new>.json
python3 docs/specs/intermediate-v1/fixtures/data/generate_fixtures.py --check
python3 docs/specs/intermediate-v1/tools/seal_spec.py --check
```

## Site architecture (`dist/`)

- **No bundler.** `index.html` loads `app.js` as an ES module, and `app.js` does `import * as C from './core.js'`.
- **`core.js` is pure logic, testable in Node.** It covers:
  - learner state in `localStorage` under `llm-foundations-v1` (load, save, merge, export);
  - the byte/BPE tokenizer, run with the saved merge rules (`validateTokenizer`, `tokenize`, `visiblePiece`);
  - shifted-target prediction, tensor-shape calculation, and run-record import validation (`parseRunFiles`, `validateRun`).
- **`app.js` is UI state plus template functions.** It holds module-level mutable UI state and template functions that return HTML strings (`home()`, `roadmap()`, `lesson(id)`, `explorer(tool, id)`, `results()`, `shapesView()`, `tokenizerView()`, …). A hash router serves `#/lesson/05`-style routes, and `init()` is called on the last line. All interpolated text goes through `C.escapeHTML`.
- **Keep two lines of `app.js` exactly as they are.** `qa/templates.mjs` evaluates `app.js` in `node:vm` by deleting the exact line `import * as C from './core.js';` and the trailing `init();`. If either changes, the template checks break.
- **Generated files.** `dist/content.json` (lessons, references, tokenizer cases, the two recorded runs), `dist/course/`, `dist/course.zip` and `course/` are all generated by `scripts/sync_course.py` from the canonical package. Don't edit them by hand. `qa/source-hashes.json` is a receipt: `sync_course.py` refuses to run if the source drifted, and the audit re-checks every hash.
- **Scripts not to re-run.** `scripts/refine.py` is a one-off patch that has already been applied. `scripts/publish-source.mjs` was the one-time initial Site publisher, and it refuses to run once the remote exists.

`DESIGN.md` records the visual and interaction rules. They include that reading, practice, checks and evidence are separate states; that no quiz gates navigation; and that simulations are labelled as such and never autoplay. `QA_REPORT.md` lists what has and hasn't been browser-tested.

## How the specification constrains the whole repo

- **The spec seals itself.** `spec-manifest.json` seals every file under `docs/specs/intermediate-v1/` except `reviews/**` (revision 1.1 payload: `f611ddde…`). Editing a sealed file needs a new revision: amend the files, run `check_spec.py --write-index --revision X.Y --report reviews/<new>.json`, delete `spec-manifest.json`, run `seal_spec.py`, then run all five checks.
- **The spec also freezes the current site.** `evidence/source-baseline.json` pins SHA-256 values for all 107 pre-existing tracked files: `dist/`, `course/`, `qa/`, `scripts/` and the root `.md`/`.gitignore`/`.openai` files, at baseline commit `3a47ea4`. `check_spec.py` fails if any of them changes, so a change to the existing site is also a specification change. Section S0 of `08-DELIVERY-AND-ACCEPTANCE.md` names this protected-file gate.
- **How to read the spec.** Read the numbered documents `00`–`08` in order. `08` holds the implementation order and release gate, and `07` the cross-document joins and limits. A conflict between prose, schema and fixtures blocks implementation and needs an amendment.
- **Machine-readable contracts.** These live in `contracts/` (`openapi.json`, schemas, `error-vocabulary.json`, `evidence-roles.json`, `semantic-rules.json`), `fixtures/` and `trace/`. Each `trace/` file holds one area's requirements and acceptance cases; `check_spec.py --write-index` generates `requirements.json` and `acceptance-cases.json` from them.
- **Keep files byte-exact.** Line endings must stay LF. This checkout sets `core.autocrlf=false`. Windows Git's default (`autocrlf=true`) writes CRLF and breaks every hash check.
