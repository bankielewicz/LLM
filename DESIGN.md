# Design system and interaction choices

The visual direction is a quiet technical workshop: a narrow, stable course outline; a generous reading measure; a small number of clearly labeled working surfaces. System sans-serif supports controls and body text, Georgia marks major learning transitions, and monospace separates IDs, shapes, commands, and recorded identities.

Light surfaces use cool gray and white with ink-blue text. Dark surfaces use navy with pale text. Blue identifies token addresses, violet vectors, brown model weights, orange targets, and green measured results. Every diagram also uses explicit text labels. The expandable diagram key introduces these identities once without imposing a legend on the first lesson.

Home foregrounds one Start/Continue action and moves the full roadmap behind a secondary link. Lessons preserve all canonical Markdown, including commands, tables, checks, answer explanations, and stopping points. Optional disclosures hold answer feedback and common misconceptions. A small rhythm strip, in-page links, related explorer links, and previous/next controls establish a repeatable session.

Reading, practice, correctly answering a knowledge check, and self-reviewed evidence are separate states. No quiz gates navigation. No lesson status awards capstone points. The capstone carries the supplied five-category, 100-point rubric, but the application does not grade artifacts it has not inspected.

Tokenizer exploration executes the exact saved byte/BPE encoding algorithm in JavaScript. It is labeled actual encoding, without model training. Shifted-target and attention views are manual-step structural simulations, with reset and a complete static matrix. Shape views compute dimensions without executing a model. Recorded metrics use distinct solid/dashed series and a full table. Best observed evaluation and latest recorded evaluation are described separately from unverified checkpoint files.

Responsive rules collapse the rail, stack split views, wrap controls, and put wide code/tables in labeled scroll regions. Mobile navigation moves focus into its links and Escape restores the menu button. Routes focus the main heading region. Focus is visible, themes persist, reduced-motion rules disable animation/transition/smooth scrolling, and all simulations avoid autoplay. These behaviors are implemented; native browser validation remains outstanding.
