## Shared release decisions
D01. Target user: adult beginner with basic Python/terminal familiarity progressing to independent applied LLM experimenter. No claim of certification or measured educational effectiveness.
D02. Required content: existing 00-12; applied modules 13 Data clinic, 14 Training diagnosis, 15 Evaluation and uncertainty, 16 Pretrained baseline, 17 Adapter fine-tuning, 18 Generation and conversation, 19 Packaging and reuse, 20 Independent applied capstone. Two shipped electives: E01 Safe model modification (weight tying), E02 Retrieval with evidence. An optional prerequisite refresher P00 is shipped; it does not count toward intermediate completion.
D03. Product modes: hosted/static reader continues to support simulations and imported records only; local companion serves the same reader plus API at http://127.0.0.1:8765, same origin. Hosted-to-local bridge, public servers, remote GPU/cloud jobs, multi-user accounts, billing and Unsloth integration are excluded. No live button enabled in static mode.
D04. Supported release profiles: win-cpu (Windows 11 x86_64, Python 3.12, float32 CPU); wsl-cpu (Ubuntu 24.04 under WSL2 x86_64, Python 3.12, float32 CPU); wsl-cuda (same WSL profile, NVIDIA CUDA supported by pinned Torch build, explicit opt-in). CPU completion path for every required lesson; CUDA is an acceleration profile, never silent fallback. macOS, native Linux outside WSL and non-NVIDIA accelerators are not release-qualified.
D05. Preserve canonical lab CLI as legacy backend. Add companion-owned tiny-v2 backend by versioned copy/refactor outside course/ for features needing instrumentation, standalone tokenizer training, test evaluation, portable artifacts, graceful cancellation or model changes. Shared pure training mechanics must have equivalence checks against unchanged legacy tests. No direct editing of original Python labs. Portable reuse uses distinct validate_bundle (read-only) and import_bundle (validated registration into a fresh local registry) operations.
D06. Named operations: tokenizer_train, tiny_train, tiny_resume, evaluate, context_preview, generate, model_prepare, adapter_train, adapter_resume, chat_generate, retrieval_build, retrieval_query, export_bundle, validate_bundle, import_bundle. Training tokenizer never creates learned neural weights; generation/evaluation never update weights; resume loads checkpoint including optimizer/RNG; adapter training starts from selected pretrained base and freezes it.
D07. Job states: queued -> starting -> running -> completed|failed|interrupted. Request cancellation sets cancelling (from queued/starting/running); queued cancellation -> interrupted with no checkpoint; running cancellation -> interrupted after supported safe checkpoint boundary. Unexpected service/process loss becomes interrupted on recovery, never completed. Exactly one compute worker at a time; at most eight queued jobs; no parallel training/generation. Runtime author owns precise state/timeout contract. Integration requirements in 07 bind checkpoint/preview/limit joins.
D08. Default limits: 1 MiB JSON API body, 10 MiB per dataset file, 30 MiB dataset upload total, 200,000 UTF-8 training-text bytes for legacy/tiny training (after JSON parse), 20 MiB total pretrained SFT text, 100,000 records total per dataset, 2000 optimizer updates per submitted training job, 512 new tokens per generation, 60 minutes per compute job. Dataset/service upload policy is distinct from preserved legacy recorded-import 1 MB UI policy. The complete authoritative limits, units and rejection map are INT-007.
D09. Applied backend: Hugging Face Transformers + PEFT, no required TRL/Unsloth dependency. One allowlisted baseline HuggingFaceTB/SmolLM2-135M-Instruct pinned to repository revision 12fd25f77366fa6b3b4b768ec3050bf629380bac. Public metadata verified 2026-09-28 and retained in evidence/model-config-and-license.json; Apache-2.0; LlamaForCausalLM; max positions8192. Select float32 CPU, no quantization. Effective teaching context512, LoRA r8/alpha16/dropout0 on q_proj,v_proj only; AdamW lr0.0002. Applied author owns complete deterministic recipe, masks, seed, batching, resume, templates, and decoding. Download requires explicit learner action and permits listed safe files only; no trust_remote_code or pickle weights.
D10. Proposed dependency baseline is Python 3.12; torch2.8.0 CPU/cu126 by profile, transformers4.57.1, peft0.17.1, accelerate1.10.1, safetensors0.6.2, fastapi0.116.1, uvicorn0.35.0, pydantic2.11.7. These are implementation target pins, not a tested compatibility assertion. Final release requires per-profile lockfiles and native qualification; a change to these selections requires a documented amendment, not opportunistic upgrades.
D11. Assets and progress: companion-owned directory selected at launch, default ~/.llm-foundations; service persists jobs, dataset/model/checkpoint registry, evidence and notes; SQLite metadata plus immutable artifact directories, atomic writes. Browser preserves foundation localStorage v1 and uses the intermediate-v1 sidecar for expanded static progress/notes/claims; v2 learning-state has explicit export/import migration, no implicit origin sharing. Data/artifact author owns schemas and migration/merge rules; credentials are never in exports.
D12. Product navigation: Home, Learn, Lab, Runs, Playground, Notebook, Evidence; Settings contains runtime/storage/accessibility. New technical settings are progressively disclosed. All primary actions usable by keyboard; native HTML first, WCAG2.2 AA target with concrete acceptance at widths360/768/1440, 200% text resize, 400% zoom/reflow, reduced motion and forced colors. UX author owns exact routes/screens/states/labels and accessibility tests.
D13. Progress has independent reading/read/practiced/self_checked flags; assessment distinguishes artifact_verified and assessor_reviewed. Deterministic verification checks artifacts and objective criteria only. Written reasoning uses explicit rubric scored by a human/self assessor identified as such; never claim an automatic competency grade from checkbox/progress. Required intermediate outcome covers modules 13-20 plus existing foundation capstone evidence. Electives have separate badges and cannot substitute required evidence.
D14. New sample datasets are authored deterministic fixtures, no automatic external corpora or generated ground-truth labels. Curriculum/data/applied authors coordinate exact counts/split/task/metric oracles. Real learner-supplied text receives audit and provenance notes; synthetic practice cannot establish general language skill. E02 uses lexical TF-IDF retrieval, no second embedding model/download.
D15. Chat is isolated by selected checkpoint/model identity. Tiny-v2 remains prompt continuation; chat uses pretrained/adapter backend. UI shows raw serialized context and truncation information. Chatting never trains; conversations do not enter training datasets without an explicit export then selected import.
D16. No guaranteed training speed, quality gain, hardware fit or graduation time. Presets have bounded compute and measurable outputs. Acceptance is executable behavior/evidence, not a promised loss threshold.
D17. Existing browser-policy block remains. This task reviews specifications only; product behavior tests are NOT_RUN. Do not launch browser or alternate renderer.
