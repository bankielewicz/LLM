# Data, storage and artifact contract — Intermediate buildout v1

Status: target specification. No behavior here is claimed to exist. **MUST** and **MUST NOT** are normative. JSON instances MUST validate with JSON Schema draft 2020-12.

The preserved v1 browser stores `llm-foundations-progress-v1`, validates at most twenty imported runs, and merges notes and flags ([baseline `dist/core.js` lines 1–24](../../../dist/core.js)). The preserved lab writes configuration, hashes, metrics, checkpoint state and result status and refuses changed data on resume/evaluate ([baseline `course/labs/lab.py` lines 79–180 and 231–248](../../../course/labs/lab.py)). Its loader detects exact duplicates only ([baseline `course/labs/data.py` lines 8–31](../../../course/labs/data.py)). These remain legacy evidence; v2 records are separate.

## DAT-001 — Storage authority and trust classes

The storage root MUST be selected before mutation; default `~/.llm-foundations`. The resolved path MUST be visible in Settings and logs. The total committed companion-root quota is exactly 50 GiB (53,687,091,200 bytes); a mutation that would cross it returns `REGISTRY_LIMIT` before writing. The service is sole writer. Browser requests MUST use registry IDs, never arbitrary host paths.

Every object has `origin`: `locally_created`, `imported`, `legacy_imported`, or `shipped_fixture`. `locally_created` means the companion completed the creating job. `shipped_fixture` requires a release-registry digest match. Validation, copying, viewing, importing or re-exporting MUST NOT upgrade imported provenance or assert local Python execution. A local job may consume imported inputs, whose origin remains in lineage.

Static mode retains v1 `localStorage` and stores intermediate learning state separately under key `llm-foundations-intermediate-v1`. Before every static write, `JSON.stringify(value).length * 2` MUST be at most 4 MiB (4,194,304 bytes) and live notes MUST be at most 100; otherwise the write is rejected without replacing the prior value. Static state may contain progress, notes, conversations and imported evidence claims, but MUST NOT create `artifact_verified` or `independently_reviewed`. The companion owns its own v2 state, jobs, metadata and artifacts. There is no implicit origin/localStorage synchronization.

## DAT-002 — Identity and immutable artifacts

Primary IDs MUST be companion-generated lowercase UUIDs: `artifact_id`, `dataset_id`, `job_id`, `run_id`, `model_id`, `checkpoint_id`, `evidence_id`, `note_id`, `assessment_id`, and `installation_id`. Imported IDs are historical labels, never local keys. Timestamps are UTC RFC3339; SHA-256 is 64 lowercase hex over exact bytes.

Artifacts validate against [`artifact-descriptor.schema.json`](contracts/schemas/artifact-descriptor.schema.json). `display_name` is text, not a path. Companion `relative_path` matches `objects/<first-two-digest>/<digest>/<safe-name>`. No absolute path is returned. Preview is `text`, `metadata_only`, or `download_only`; only UTF-8 text formats at most 262,144 bytes may be `text`. Larger text downloads. Weights, checkpoints and archives are download-only. Bytes are immutable; changes create new IDs/digests/lineage. Physical byte deduplication does not collapse logical IDs.

## DAT-003 — Dataset registration, audit and fixtures

Datasets validate against [`dataset-manifest.schema.json`](contracts/schemas/dataset-manifest.schema.json). Multipart upload permits at most three JSONL files, each at most 10 MiB and 30 MiB combined, and 1–100,000 parsed records. Tiny-v2 training permits at most 200,000 UTF-8 training-text bytes; applied SFT permits at most 20 MiB parsed message/response content. The 1 MiB JSON API limit is separate.

Each nonblank line is an object. `document_text_v1` has `record_id`, `scenario_group_id`, `text`, optional `slice`. `instruction_intent_v1` has those IDs, `messages`, `expected`, `slice`; applied-intents has exactly one user message, `expected.intent` equals slice, and `expected.response` is canonical. IDs are unique. Text is valid UTF-8, no NUL, non-whitespace. Train/validation/test group IDs are disjoint for training eligibility.

Registration creates [`data-audit.schema.json`](contracts/schemas/data-audit.schema.json) before eligibility. Audit records byte/record/split/slice counts, exact pairs, normalized-near pairs, group overlaps and rejections. Unordered pairs count once. Exact content compares bytes. Near normalization is Unicode NFKC, casefold, replace punctuation/symbol scalars with ASCII space, collapse Unicode whitespace, trim; normalized-equal nonexact pairs count. Group overlap counts distinct group IDs in multiple splits. Any cross-split exact/near pair or group overlap makes `eligibility:"audit_only"`; training, selection and final evaluation reject it. Test content is unavailable to training/selection; audit records whether a run consumed final test.

Frozen fixture counts/splits/oracles are in [`fixtures/data/canonical-fixtures.json`](fixtures/data/canonical-fixtures.json); all source texts, templates and fact tables are fixed in [`fixtures/data/fixture-source.json`](fixtures/data/fixture-source.json). [`fixtures/data/generate_fixtures.py`](fixtures/data/generate_fixtures.py) defines the retained JSONL and hash inventory under [`fixtures/data/materialized/`](fixtures/data/materialized/), asserting leakage and TF-IDF oracles. `python fixtures/data/generate_fixtures.py --check` regenerates bytes in memory and compares without writing; `--output <new-unused-directory>` writes only after exclusive directory creation and never deletes an existing path:

- `data-clinic-v1`: 48 authored synthetic support notes, twelve scenario groups x four variants; DC01–06 train (24), DC07–09 validation (12), DC10–12 test (12); zero leaks.
- `data-clinic-leaky-v1`: audit-only mutation with exactly one cross-split exact pair, two cross-split normalized-near pairs, and one overlapping group.
- `diagnosis-v1`: recipes referencing clean/leaky data, never fabricated measurements.
- `applied-intents-v1`: 84 authored synthetic instructions in six slices (`account_access`, `billing_refund`, `order_status`, `password_reset`, `product_information`, `technical_issue`), fourteen groups each; 10/2/2 groups per slice and totals 60/12/12.
- `capstone-support-v1`: 48 authored examples, six slices x eight groups; five groups/slice train (30), one validation (6), and two sealed test (12). Sealed records/labels are inaccessible until one final paired evaluation per capstone attempt.
- `retrieval-manual-v1`: eight authored documents and six queries with fixed top-3 IDs and citation-support labels under the applied TF-IDF contract.

No external corpus, generated ground-truth label or implied license belongs to these fixtures. Materialized `sealed_test.jsonl` maps to logical API split `test` with the capstone sealed policy; it is never an ordinary user-uploaded test bypass. Stored fixture manifests may retain `sealed_test` as the source label, but all evaluation requests use `split:test` plus the capstone attempt/token binding.

Sealed attempts validate against [`capstone-attempt.schema.json`](contracts/schemas/capstone-attempt.schema.json). Creation returns [`capstone-attempt-created.schema.json`](contracts/schemas/capstone-attempt-created.schema.json) exactly once with a 43-character base64url release token; persistence stores only its SHA-256 and GET/list never return the secret. A token binds dataset ID, manifest digest and sealed split, and is never returned with split content. One atomic evaluate request MUST name exactly two subjects in order `[frozen_baseline, selected_candidate]`. The service consumes the token before reading test bytes; failure, cancellation or process loss leaves it consumed. The paired artifact uses identical ordered test IDs for both subjects, retains raw outputs and metric deltas, and no endpoint exposes sealed records before consumption.

A consumed token cannot be retried or reset. A dataset-exposure ledger keyed by dataset manifest digest is set before any sealed bytes are read and remains set after completion, failure, cancellation or process loss. The first token is labelled `fresh_test`; every later token for that digest is `reused_test`, even if no output survived. After failure/cancellation the learner may explicitly create a new attempt with a fresh `attempt_id`, freeze and token, while the prior attempt remains immutable. A reused-test result may support debugging/comparison but MUST NOT be labelled an independent untouched-test result or satisfy an untouched-test evidence criterion. Reports show both attempt history and exposure label.

## DAT-004 — Jobs, runs, metrics and results

Jobs validate against [`job-record.schema.json`](contracts/schemas/job-record.schema.json). Operations are `tokenizer_train`, `tiny_train`, `tiny_resume`, `evaluate`, `context_preview`, `generate`, `model_prepare`, `adapter_train`, `adapter_resume`, `chat_generate`, `retrieval_build`, `retrieval_query`, `export_bundle`, `validate_bundle`, `import_bundle`. `context_preview` loads tokenizer/template metadata only, never weights or inference, and emits an immutable preview artifact binding subject, tokenizer/template digests and canonical generation request excluding preview reference; any request edit invalidates it. Runtime transitions are defined in [04-RUNTIME-AND-API.md](04-RUNTIME-AND-API.md); the database retains each event with time and monotonic sequence. Request JSON, resolved IDs, profile, app version and installation remain even if no run is created.

Runs validate against [`run-manifest.schema.json`](contracts/schemas/run-manifest.schema.json) and bind operation/backend/config, dataset split artifact IDs/digests, tokenizer/model identity, seed, dependency-lock digest, profile/device and parent IDs. Resume creates a new run and never overwrites its parent. Inapplicable fields are absent.

Each [`metric-record.schema.json`](contracts/schemas/metric-record.schema.json) event has increasing sequence, nondecreasing step, finite values, unit, protocol and time. NaN/infinities and strings are invalid. Standard names are `train_nll_token`, `validation_nll_token`, `gradient_l2_norm`, `elapsed_seconds`; missing is absent, never zero.

[`run-result.schema.json`](contracts/schemas/run-result.schema.json) requires completed training's requested/final steps equal. Interrupted reports last durable checkpoint and may stop early. Failed may omit requested step and retains bounded plain-text error. It distinguishes last observed from durable step. Recovered process loss is interrupted.

`test_nll_bytes_v1` includes aggregate `negative_log_likelihood_sum`, `utf8_bytes_sum`, `record_count`, `nll_per_utf8_byte`; per-record ordered `record_id`, `utf8_bytes`, `token_count`, `negative_log_likelihood`, `nll_per_utf8_byte`; worst three sort descending metric then ascending ID. Applied evaluation retains ordered IDs/raw outputs and overall/per-slice `exact_intent_match` and `response_schema_valid_rate`. Intent is first nonempty `INTENT=<allowed-slice>`. Schema-valid output is exactly two nonempty lines, second `REPLY=<nonempty <=240 Unicode scalars>`. No threshold implies competency.

For a `test_nll_bytes_v1` metric, top-level `value` MUST equal payload `nll_per_utf8_byte`. For `applied_intents_v1`, top-level `value` MUST equal overall `exact_intent_match_ratio`; overall and every slice MUST retain `record_count`, both integer match counts, and both ratios. Each ratio MUST equal its corresponding count divided by `record_count`, with no rounding in stored JSON. The response metric's learner-facing label is `response_schema_valid_rate`; the schema field is `response_schema_valid_ratio`.

The evaluation records artifact MUST prefix every row with integer `subject_index`. Single-subject evaluation uses only `0`; sealed paired evaluation uses `0` for frozen baseline and `1` for selected candidate. Both subject blocks MUST contain the identical ordered record IDs; missing, repeated or reordered IDs reject the result artifact.

## DAT-005 — Checkpoint identity and lineage

Checkpoints validate against [`checkpoint-descriptor.schema.json`](contracts/schemas/checkpoint-descriptor.schema.json), binding bytes, run/job, backend, step, model/profile, tokenizer/chat-template digests, dataset IDs/digests, seed, lock digest, dtype and profile. Applied identity binds repository `HuggingFaceTB/SmolLM2-135M-Instruct`, revision `12fd25f77366fa6b3b4b768ec3050bf629380bac`, manifest/tokenizer/template digests and profile version. Adapter fields are `r:8`, `lora_alpha:16`, `lora_dropout:0`, `target_modules:["q_proj","v_proj"]`, `bias:"none"`, `task_type:"CAUSAL_LM"`; identity also records dataset digest, dependencies, device, seed, steps, batch, accumulation, LR, weight decay, max gradient norm, context and eval/save cadence.

Every checkpoint descriptor declares `portability` (`inference_only`, `resume`, or `metadata_only`) and `contains_resume_state`. Only `resume` has true resume state; resume endpoints reject `inference_only`. Legacy opaque descriptors are always `metadata_only`. Bundle validation returns `schema_version:1` and `readiness`: `base_required` if any portable applied subject lacks its exact verified base; otherwise `ready` if at least one selected subject has portable inference weights; otherwise `metadata_only`. This describes artifact availability, not a successful inference test.

Portable imported weights MUST be safetensors plus JSON config. Pickle, marshal, Torch `.pt`/`.pth` and arbitrary code are forbidden in bundles/download imports. Local preserved-lab `.pt` may register only as `legacy_opaque_checkpoint`; uploaded/imported legacy `.pt` is never deserialized, and a v1 run record creates no checkpoint.

Lineage edges are `created_from`, `resumed_from`, `adapted_from`, `evaluated`, `generated_with`, `copied_from_bundle`; cycles are invalid. Import assigns fresh IDs and retains `source_identity` with bundle digest, source installation/type/ID. Duplicate imports never collapse logical lineage.

## DAT-006 — Progress, notebook, evidence and conversation

[`progress-v2.schema.json`](contracts/schemas/progress-v2.schema.json) stores independent `reading`, `read`, `practiced`, and `self_checked` booleans with per-dimension timestamps and a revision. One dimension MUST NOT imply another. Clearing a true flag requires an explicit reset event. Progress never encodes artifact verification/assessment.

[`notebook-entry.schema.json`](contracts/schemas/notebook-entry.schema.json) has stable ID, revision, timestamps, up to 8 module IDs, 8 dataset/run/checkpoint links, 16 artifact links, and `prediction`, `observation`, `explanation`, `limitations`, `next_experiment`, each <=20,000 Unicode scalars. At most 1,000 live notes. Revisions preserve audit history.

[`evidence-record.schema.json`](contracts/schemas/evidence-record.schema.json) sets `artifact_verified` only from named/versioned deterministic checks over exact digests. Assessments validate against [`assessment-record.schema.json`](contracts/schemas/assessment-record.schema.json): `review_kind` is exactly `self` or `independent`; reviewer identity, rubric version, exactly ten immutable rubric rows, decision, rationale and time are required. Every row retains criterion ID, score limited to 0/5/10, and comment. A later review appends a new assessment and never overwrites rows. Derived `review_status` is `not_reviewed`, `self_reviewed`, or `independently_reviewed`. Imports never set verification or review status; an imported assertion of independent review remains `imported_claim` until a new local independent assessment is stored.

Evidence submission uses the closed requirement/profile pairs in [evidence-verification.md](contracts/evidence-verification.md). note_refs selects up to eight exact note ID/revision pairs; creation verifies each current or retained revision, snapshots the full notebook-entry-v2 record with its canonical SHA-256, and stores note_snapshots atomically. A missing revision rejects the whole request; later note edits/deletion never silently alter the snapshot. CUR-012 requires exactly one plan snapshot whose original revision creation time predates the candidate training job. Note content copied into evidence is shown in the submission preview and follows explicit evidence export selection. CUR-015 alone requires structured_response with six fixed-order RQ01–RQ06 citations (query_id, record_id, span_start_utf8, span_end_utf8). Offsets are half-open, nonempty, within exact source UTF-8 bytes, and both end on scalar boundaries; the verifier checks the cited returned document/support rule. Other requirement IDs forbid structured_response. Module15 error-analysis spans/categories stay human-assessed claim_text. No structured field or note truth is inferred from its presence.

New evidence stores verification_checks as an empty array. Each verification response persists the ordered bounded check outcomes with check_id, PASS/FAIL/NOT_RUN, received_value and expected_rule as escaped plain text, and artifact_ids. Failed or incomplete verification never upgrades verification_status. Named checks use the verification_profile_id followed by a period and a zero-padded three-digit ordinal in the mapping paragraph order; predicate clauses separated by semicolons receive consecutive ordinals. Any verifier revision that changes this ordering increments its version. Detailed artifact evidence remains downloadable; the result list truncates neither required checks nor identifiers.

intermediate_evidence_packet_complete is read-only and derived true exactly when requirement_id is CUR-012, claim_status is local_submission and verification_status is artifact_verified with all current prerequisites valid. It is false for every other record, static state and imported claim; clients cannot submit it. This is artifact completeness, not a passed human assessment.

Assessment semantic validation recomputes the integer total from the ten rows. `decision:"meets"` is accepted only when objective gates recorded by the curriculum verifier all pass, total is at least 80, and no row is zero. The server stores `total_score` and `objective_gates_verified`; the client cannot set either. Decision is `partially_meets` when the meets predicate fails and total is at least 50, otherwise `does_not_meet` for total below 50. Any client decision inconsistent with this derivation is rejected with HTTP 400 `VALIDATION_FAILED` at field `decision`. The arithmetic rules are also enumerated in [semantic-rules.json](contracts/semantic-rules.json). Review status describes who reviewed, not whether the decision was `meets`.

Conversations validate against [`conversation.schema.json`](contracts/schemas/conversation.schema.json) and bind one immutable base model plus optional adapter checkpoint. Each turn content is at most 1 MiB (1,048,576 UTF-8 bytes) and all live turn content in one conversation totals at most 1 MiB; both are semantic byte checks in addition to schema string bounds. A conversation append endpoint accepts expected revision plus a completed `chat_generate` output artifact and atomically appends its bound user and assistant turns. Cancelled, interrupted, partial, subject-mismatched or request-mismatched generation artifacts are rejected. Stored generation evidence includes turns, serialized input, input token count, dropped indices, context limit, decoding, output token IDs/text and stop reason. Model changes start a new conversation. Conversation export creates an inert JSONL dataset-candidate artifact; it becomes training data only through ordinary dataset import/audit.

## DAT-007 — Legacy v1 migration

The companion accepts user-selected v1 backup matching [`legacy-progress-v1.schema.json`](contracts/schemas/legacy-progress-v1.schema.json), portable v2 learning state matching [`learning-state-backup.schema.json`](contracts/schemas/learning-state-backup.schema.json), and run files matching [`legacy-run-v1.schema.json`](contracts/schemas/legacy-run-v1.schema.json). Automatic localStorage reading/origin probing is forbidden. Before preview, exact input bytes become immutable source backup.

Preview validates without mutation and reports accepted/skipped/duplicate/conflicting lesson, note, evidence and run counts plus field errors. It may return transient conflict handles but MUST NOT allocate or promise permanent local IDs. Apply includes preview digest and explicit confirmation; changed bytes or database revision invalidates it. Apply is one transaction and its response is the first source of original-to-new local ID mappings.

Each v1 `reading`, `read`, `practiced`, and `checked` flag maps only to v2 `reading`, `read`, `practiced`, and `self_checked`, respectively; absent means false. No flag promotes another. Nonempty notes become one imported Markdown note retaining labels. Evidence becomes `claim_status:"imported_claim"`; legacy `reviewed` survives only under `legacy_claim`, never verification/assessment. Runs become `legacy_imported` snapshots with `execution_attestation:"unverified_import"`; tokenizer digest may be validated, but paths/checkpoints are not imported and local execution is not claimed.

## DAT-008 — Merge, collisions and duplicate imports

Bundle objects always receive fresh IDs; internal references are rewritten through an atomic complete old-to-new map. `source_identity` detects repeat imports. Preview reports duplicates. Apply `duplicate_policy:"skip"` creates nothing for them; `copy` creates new logical copies linked `copied_from_bundle`. There is no overwrite.

Progress merge ORs each independent flag and records both source revisions; it grants no verification and never infers one flag from another. Same original note ID with different digest retains both, suffixing imported title with short bundle digest. Equal digest with skip is skipped. Evidence/assessments never coalesce by text. Registry identity is digest plus lineage, not display name.

Any invalid object, dangling reference, lineage cycle, checksum/limit violation rejects the entire import before mutation. Partial merge is forbidden.

## DAT-009 — Bundle and path safety

Bundle is ZIP `.lfbundle`, MIME `application/vnd.llm-foundations.bundle+zip`, rooted at `llm-foundations-bundle/manifest.json` and validating against [`bundle-manifest.schema.json`](contracts/schemas/bundle-manifest.schema.json). Manifest lists every other regular file with exact uncompressed size, SHA-256, media type, type and original ID. Canonical manifest is UTF-8 JSON, sorted keys, no insignificant whitespace, one trailing LF; `payload_sha256` hashes concatenated lowercase entry digests in manifest order, excluding manifest.

Export uses seekable staging, fixed DOS timestamp `1980-01-01 00:00:00`, UTF-8 names, deterministic manifest order, and DEFLATE level 6 (stored method for zero-byte files), then fsyncs, self-validates and atomically renames. Import validates before extraction/mutation. Limits: 1 GiB archive, 2 GiB declared/actual unpacked, 10,000 entries, 512 MiB each, path <=240 UTF-8 bytes, compression ratio <=100:1 per entry and total. Reject duplicate/case-fold-colliding names, encryption, data descriptors, multi-disk, out-of-limit ZIP64, comments, every extra field except required ZIP64 size fields, and trailing bytes.

Paths are relative POSIX under `llm-foundations-bundle/objects/`, characters `[A-Za-z0-9._/-]`; reject empty/`.`/`..` components, backslash, colon, absolute/drive/UNC/control forms, trailing dot/space and Windows device names. Do not percent-decode. Only regular, nonexecutable files; reject links/devices/FIFOs. Extract create-new into a fresh staging directory; resolve-beneath check, stream size/digest verification, fsync, then register. Failure removes only staging.

`validate_bundle` is read-only; `import_bundle` revalidates. Exports exclude credentials, tokens, environment variables, absolute paths, browser keys and secrets. Export preview lists selected notes/conversations because learner text may be sensitive.

## DAT-010 — SQLite and atomic writes

SQLite MUST enable foreign keys, WAL and `synchronous=FULL`. `user_version` begins at 1. Startup migration takes exclusive lock, writes and validates `backups/metadata-v<old>-<timestamp>.sqlite3`, migrates in one transaction, sets version, runs foreign-key check, commits. Failure rolls back and starts read-only recovery.

Tables separate objects, artifacts, lineage, jobs/events, progress, note revisions, evidence, assessments, import maps and migrations. Every mutating request is one transaction. Artifact creation streams exclusively to `staging/<job-id>/<random>.partial`, enforces limits/digest, fsyncs file/directory, atomically renames to content-addressed storage, then commits rows. A post-rename DB failure leaves an orphan eligible for deletion only after 24 hours and proof no descriptor references it. Registry rows never reference missing bytes; job completion commits artifacts and result together.

## DAT-011 — Disk-full, corruption and recovery

Preflight estimates writes and rejects `INSUFFICIENT_STORAGE` when free space is below estimate plus 1 GiB. ENOSPC, short write, fsync/rename failure stops work, never completes, removes only job staging where possible, and records retryable failure; committed artifacts remain unchanged.

Startup runs SQLite quick-integrity/foreign-key checks and verifies every artifact's existence and size. The service recomputes an artifact digest before any use, preview, download, bundle export, model load or evidence verification. Corrupt DB or missing/mismatched artifact enters read-only recovery: content and export of independently healthy bytes remain available; training/import/merge/deletion/verification/bundle creation are disabled. UI names failed check and newest valid backup. Never auto-restore. Explicit restore validates backup/references, preserves corrupt DB as recovery artifact, then atomically swaps.

## DAT-012 — Export trust, retention and deletion

Export is a copy, not computation proof. Validation establishes structure and bytes only. UI/reports show origin/source identity and verification status. Imported outputs/text are untrusted and escaped in HTML/logs.

Deletion previews dependents and removes live references transactionally. Shared bytes remain while referenced. Garbage collection requires 30-day grace and tombstone ID/digest/size/time/reason. Job events, import mappings and evidence/assessment audits are append-only. Learner may delete note/conversation content; audit retains only IDs, times and content digest.

## DAT-013 — Contract validation

Schemas use draft 2020-12 with UUID/date-time format assertions; unknown properties are rejected except versioned metric payloads. Fixtures are contract inputs, not product PASS evidence. Cases are frozen in [`trace/DAT.json`](trace/DAT.json). Rejections use runtime envelope `{error:{code,message,field_errors:[{field_path,message}],retryable,request_id}}`; validation precedes mutation and rejection leaves DB revision, registry counts and artifact tree unchanged.

Validation order MUST be transport size, archive structure, UTF-8/JSON syntax, schema, cross-reference, checksum, semantic invariant, then eligibility. The first failing stage supplies the top-level error code; all safely discoverable field errors from that stage are returned in deterministic lexical `field_path` order. Required codes are `PAYLOAD_TOO_LARGE`, `ARCHIVE_UNSAFE`, `INVALID_ENCODING`, `INVALID_JSON`, `SCHEMA_INVALID`, `REFERENCE_MISSING`, `CHECKSUM_MISMATCH`, `SEMANTIC_INVALID`, `DATASET_INELIGIBLE`, `DUPLICATE_SOURCE`, `INSUFFICIENT_STORAGE`, and `STORAGE_CORRUPT`. Parse exceptions and host paths MUST NOT appear in the public message. The service log may contain an internal correlation value matching `request_id`, but MUST redact learner text and credentials.

Semantic validation MUST enforce invariants that JSON Schema cannot express. Metric sequences strictly increase; steps never decrease; completed training final/requested steps match; durable checkpoint step does not exceed observed step; run and checkpoint IDs referenced by evidence exist; every artifact descriptor size/digest matches bytes; dataset totals equal split totals; per-slice totals equal split contents; applied intent equals the record slice; group IDs do not cross eligible splits; lineage is acyclic; imported object references resolve inside the same import map or an explicitly declared existing local dependency. `subject_index` blocks have complete identical record-ID order. A sealed token's dataset digest and attempt freeze match the evaluation request.

SQLite minimum columns are binding even if implementation names differ internally. Object tables store local ID, format/version, origin, source identity JSON, content revision, created/updated time and deleted time. `artifacts` stores descriptor fields and refcount is derived, never trusted as sole deletion authority. `lineage_edges` has source ID, target ID, edge type and creating job, with unique tuple and cycle check. `jobs` stores request digest, state and terminal result/error; `job_events` is keyed by job plus sequence. Progress is keyed by module; note revisions by note plus revision; evidence and assessments use immutable rows. `imports` stores bundle digest, preview digest, database revision, policy, completion and old/new mapping artifact. Every foreign key uses RESTRICT except deletion tombstone relations explicitly documented by migration.

Fixture generation MUST use the registry and authored source order/formulas exactly. Record serialization uses UTF-8 without BOM, LF, JSON keys sorted by Unicode code-point order, compact separators, and one trailing LF per JSONL record. There is no random shuffle. Split files are emitted in declared split order; inside a split, slice order is the registry's six-slice order, then numeric group ordinal, then declared variant order. Re-running generation with the same release MUST produce identical bytes and registered digests on every supported profile. Implementation MUST NOT invent, paraphrase or externally generate fixture text.

For `capstone-support-v1`, `attempt_id` is a local UUID and the freeze record binds baseline model/checkpoint, candidate model/checkpoint, dataset ID/digest, decoding/evaluation config and creation time. Creating a new attempt requires an explicit learner action and a reason enum `first_attempt|prior_failed|prior_cancelled|new_experiment`; it MUST NOT copy verification or assessment from a prior attempt. Only `prior_failed` and `prior_cancelled` may follow an attempt that has no completed paired artifact. A completed paired evaluation prevents another attempt for the same candidate checkpoint and dataset digest; selecting a new candidate checkpoint creates a distinguishable experiment.

Export selection MUST close transitively over dependencies required by the chosen `bundle_mode`. Request fields are `bundle_mode`, run/model IDs, `checkpoint_options:[{checkpoint_id,include_resume_state}]`, evidence/note/conversation IDs. Both `thin` and `full` bundles include selected portable tiny/adapter inference weights/config plus model profile, tokenizer/chat-template identity, creating run manifest/result/metrics, bound dataset manifests/audits/split descriptors, dependency-lock identity and lineage ancestors. `thin` omits the eight pretrained-base files and requires that exact verified base in the receiving cache. `full` also includes the base files from the allowlisted download manifest. Neither mode converts a portable checkpoint to metadata-only. Independently of thin/full, `include_resume_state:true` additionally includes optimizer/RNG state in safe portable non-pickle form and marks checkpoint portability `resume`; false marks `inference_only`. The required request object content_options contains booleans include_dataset_bytes, include_raw_outputs and include_assessments, defaulted to false by the UI but always sent explicitly. Notes and conversations use their explicit ID lists. include_assessments includes all immutable assessments attached to selected evidence. A resume selection requires include_dataset_bytes true; otherwise reject before queuing with VALIDATION_FAILED at content_options.include_dataset_bytes. Raw output exclusions never remove scalar metrics. Exclusions are recorded in `omissions`. Missing required dependency rejects export; optional omission warns. Import never resolves a dependency by display name.

Portable learning-state JSON has format `llm-foundations-learning-state-v1`, validates against the named schema, and contains progress plus selected notes, evidence claims and conversations. Its exact UTF-8 bytes MUST be at most 8 MiB (8,388,608); import uses a dedicated multipart part with that limit rather than the ordinary 1 MiB JSON API body. Legacy v1 browser backup keeps its preserved 1,000,000-byte UI limit.
