## Root and focused final findings

The first executable edge review retained one failed example and nine contract findings. Root corrected assessment criterion identity, empty rationale, duplicate criteria, score/gate decisions, invalid job state combinations, job/result and event/payload correlation, relative cadence semantic validation, and exact prepared-model file identity. The failed capstone example itself was corrected to use the defined subject discriminator. Attempts001–009 remain in the package; harness failures and rejected overwrite attempts are not product failures.

Further source comparison resolved:
- Thin bundles incorrectly omitted all weights in data/runtime prose and schema. Both modes now retain selected adapter/tiny weights; only the eight pretrained-base files distinguish full from thin. Resume is independent, and bundle aggregate resume flags equal checkpoint entries.
- API and durable conversation subjects now share one schema. The obsolete generation_id turn field was removed in favor of the shared generation_artifact_id contract.
- Stored applied presets previously named a nonexistent preset. Both real presets now constrain seed, accumulation, cadence and update bounds. Initial capstone requires exactly20, while resume has its separate remaining-update rule.
- Checkpoint descriptors now retain null/UUID parent, base-model registry identity, device, source revision, init_lora_weights and explicit portability.
- Adapter chat runs preserve their full subject; generation/chat run configs retain the preview digest and reject greedy top_p other than1.
- Live metric events contain one validation scalar per evaluation boundary, fitting the event ceiling. Full training/gradient/selection details remain in the metrics artifact.
- Service-side request/identity checks do not tokenize. The accepted worker reproduces the preview before inference and can fail CONTEXT_PREVIEW_STALE asynchronously.
- Preflight execution uses a fixed bounded child with a closed IPC schema; startup service code does not import model libraries.
- Twelve explicit evidence verifier profiles replace an ambiguous umbrella. Structured E02 citations, exact note snapshots, diagnostic receipts and read-only completion have concrete API/storage paths. Foundation verification uses companion-created reenactment; external lab records remain imported claims. E01 keeps its existing owner-control registration.

All listed findings have a specified resolution and applicable acceptance coverage. This means the inspected contradictions are closed in the authored contract. It does not guarantee that every possible implementation question has been discovered.
