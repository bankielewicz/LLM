# Local companion runtime and API

Status: normative implementation specification. This file defines the release target; it does not claim implementation or qualification. It is subordinate to [00-DECISIONS.md](00-DECISIONS.md). The machine contract is [contracts/openapi.json](contracts/openapi.json); acceptance cases are [trace/RUN.json](trace/RUN.json).

The preserved lab already separates training, resume, generation, evaluation, tokenization and inspection; refuses an existing output directory; caps training text; atomically replaces checkpoints; and records failure or interruption distinctly ([course/labs/lab.py](../../../course/labs/lab.py), lines 79-180 and 183-248). The static reader currently loads content and recorded runs in-browser and says it does not run Python ([dist/app.js](../../../dist/app.js), lines 10 and 60). These are baselines, not claims about the target companion.

KiB, MiB and GiB mean powers of 1024. UTF-8 byte length uses strict encoding. Timestamps are RFC 3339 UTC with Z and milliseconds. IDs are lowercase UUIDs generated by the companion. Digests are lowercase SHA-256 hex.

## RUN-001 — Modes, launch and discovery

The hosted/static reader MUST make no companion request. It MUST label simulations and recorded data and disable every live action with “Start the local companion to run this operation.”

The companion MUST bind only 127.0.0.1:8765, serving reader and /api/v1 on that origin. It MUST NOT bind 0.0.0.0, IPv6, localhost, LAN or public interfaces. Package/import names are llm-foundations-companion and llm_foundations_companion. Entrypoints are:

    python -m llm_foundations_companion serve --storage <root> [--profile win-cpu|win-cuda|wsl-cpu|wsl-cuda]
    python -m llm_foundations_companion gpu-check
    python -m llm_foundations_companion connect --storage <root>
    python -m llm_foundations_companion status --storage <root>
    python -m llm_foundations_companion request --storage <root> --file <request.json>
    python -m llm_foundations_companion cancel --storage <root> --job-id <uuid>
    python -m llm_foundations_companion events --storage <root> --job-id <uuid> --after <cursor>

Default root is ~/.llm-foundations. Serve prints its resolved root and fails if its lock or port is occupied; it never selects another port. On native Windows, win-cpu and win-cuda are valid; on WSL, wsl-cpu and wsl-cuda are valid. Each installed profile's environment is `envs/<profile>` inside the install directory (DEL-002). Omitting --profile selects the OS profile that matches the running environment's installed Torch build, read from package metadata without importing Torch: a `+cpu` build selects win-cpu or wsl-cpu, and a `+cu128` build selects win-cuda or wsl-cuda. Any other installed Torch version, or no Torch distribution, selects the OS CPU profile, whose preflight then reports BACKEND_MISSING or BACKEND_VERSION_MISMATCH as RUN-015 defines. An explicit --profile that does not match that build fails before the lock with BACKEND_VERSION_MISMATCH. A CUDA profile, explicit or default, starts only after a passing CUDA preflight (RUN-015); if the preflight fails, serve prints the reason code, its error-vocabulary meaning and the command that starts the OS CPU profile from its environment, then exits without publishing a lock. The companion never switches device on its own, at startup or at job time. At startup the launcher runs the fixed GPU query of RUN-015 on every profile and sets RuntimeInfo.gpu_offer. Its status is `in_use` on a CUDA profile. Otherwise it is `not_detected` when the query finds no GPU; `unsupported` with CUDA_DRIVER_TOO_OLD, CUDA_CAPABILITY_UNSUPPORTED or CUDA_MEMORY_INSUFFICIENT when the query line fails the driver (572.61), compute capability (7.5) or total memory (3,584 MiB) rule, checked in that order; and `available` otherwise. `cuda_environment_installed` is true when the running environment is `envs/<profile>` and `envs/<OS CUDA profile>` beside it contains an interpreter; `explicit_profile` records whether --profile was given. `gpu-check` runs only the GPU query, needs no Torch import, prints as one JSON line the GpuOffer that a CPU session started now would report, then prints one sentence and exits 0: `Supported GPU found: {name}. Recommended: also install the {cuda_profile} environment (setup guide, GPU section); module 17's device comparison uses both environments.` for `available` without the CUDA environment; `Supported GPU found: {name}. The {cuda_profile} environment is installed; start the companion from it to use the GPU.` for `available` with it; `GPU found but not supported: ` followed by the UX-004 reason sentence for `unsupported`; and `No NVIDIA GPU found; the CPU environment runs every lesson.` for `not_detected`. Invalid OS/profile pairs fail before the instance lock is published. The selected profile is immutable for that service instance; changing it requires a clean service stop, resolution of every nonterminal job under RUN-010, and relaunch against the same owned root. Applied operations derive device from the selected profile, never fall back to another device, and accept no HTTP profile/device mutation. Status, runtime and the P00 receipt record the selected profile and device. Connect issues pairing without stopping work. CLI requests use the same validators and limits as HTTP.

Unauthenticated GET /healthz returns only status and api_version. At startup the service runs the fixed P00 preflight in RUN-006. Authenticated GET /api/v1/runtime returns mode, api_version, runtime_version, instance_id, profile, device, gpu_offer, storage_root_display, storage_writable, server_time, exact limits (every INT-007 bound, as the const keys of RuntimeInfo.limits), and capability records with available, reason_code and message. It MUST NOT disclose credentials, internal paths, environment, package indexes or hostnames.

## RUN-002 — Package and process boundary

The package MUST preserve this responsibility direction:

    llm_foundations_companion/
      __main__.py, cli.py                 fixed commands/local-control client
      api.py, auth.py, limits.py          HTTP, pairing, boundary validation
      registry.py, database.py            registry and SQLite transactions
      scheduler.py, events.py             FIFO scheduler and event log
      worker_main.py, worker_protocol.py   fixed worker and IPC
      operations/                          allowlisted operation modules
      legacy_adapter.py                    preserved-lab compatibility
      static/, migrations/

The service process MUST NOT import Torch, Transformers or PEFT or compute with models. Each job runs in a new child with fixed argv: python -I -m llm_foundations_companion.worker_main --job-id UUID --instance-id UUID. Request data cannot change executable, module, working directory, environment names or argv shape.

A canonical request crosses an inherited pipe. Dispatch is a closed map containing tokenizer_train, tiny_train, tiny_resume, evaluate, generate, model_prepare, adapter_train, adapter_resume, context_preview, chat_generate, retrieval_build, retrieval_query, export_bundle, validate_bundle and import_bundle. Workers MUST NOT use a shell, eval, exec, dynamic imports/plugins, notebooks, uploaded code, pickle from uploads or trust_remote_code. Applied weights use safetensors. Legacy checkpoints are opened only by the fixed adapter using Torch weights_only=True, matching lab lines 26-33.

Worker environment is an allowlist for the qualified interpreter/runtime, UTF-8, profile Torch controls, job/instance IDs and staging path. Proxy, Python-path, shell-startup, credential and arbitrary parent variables are absent. Stdout and stderr are each capped at 1 MiB; truncation emits a warning. Logs are untrusted downloadable artifacts.

## RUN-003 — Pairing, sessions and browser security

Each serve generates a CSPRNG instance_id, 256-bit control secret and bootstrap secret. Root/runtime/control.json is current-user-only: mode 0600 on WSL and user-only ACL on Windows. Connect verifies instance and PID through the private control channel and prints http://127.0.0.1:8765/#/connect/SECRET without restart. The internal control endpoint requires the file secret and accepts no browser Origin.

The control channel is local IPC, never TCP. On WSL it is the Unix domain socket `<root>/runtime/control.sock` created with mode 0600 inside the 0700 `runtime/` directory; on Windows it is the named pipe `\\.\pipe\llm-foundations-<instance_id>` whose DACL grants access only to the current user SID (SYSTEM and built-in Administrators MAY remain, as for the root ACL). A connection carries exactly one request line and one response line: UTF-8 canonical JSON (INT-008 bytes) terminated by LF, at most 1 MiB each. The request object is exactly `{\"control_secret\", \"operation\", \"arguments\"}`; `control_secret` is compared in constant time with the 256-bit secret in `runtime/control.json` and is never logged. Operations are exactly `pair` (returns the bootstrap URL), `status`, `submit_job` (a JobRequest plus `idempotency_key`; idempotency scope for control requests is the instance), `cancel_job`, `list_events`, `register_e01_receipt` and `register_reuse_receipt`. The response is `{\"ok\":true,\"result\":...}` or `{\"ok\":false,\"error\":<Error.error object>}`; a wrong secret is AUTH_REQUIRED, an oversize line PAYLOAD_TOO_LARGE, a second line or unknown operation INVALID_REQUEST. Control requests use the same validators, limits, queue and registry transactions as HTTP; they bypass only Host/Origin/CSRF/bearer checks, which do not apply to local IPC. The CLI commands in RUN-001 use this channel exclusively.

Bootstrap expires in 120 seconds and is single-use. Its URL fragment never reaches HTTP, Referer or logs. JS removes it with history.replaceState, then sends it to POST /api/v1/sessions. Success invalidates it and returns independent 256-bit access_token and csrf_token, instance_id, idle_expires_at and absolute_expires_at. Invalid, expired and reused secrets share 401 AUTH_REQUIRED.

Credentials live only in sessionStorage scoped by instance, permitting same-tab reload. They MUST NOT enter localStorage, IndexedDB, URL, progress, notebook, export, log or crash report. Disconnect or expiry clears them. Sessions expire after two idle hours and 12 absolute hours; stream heartbeats do not refresh idle time. Restart invalidates sessions.

All /api requests require exact Host 127.0.0.1:8765. Session exchange and mutations require exact Origin http://127.0.0.1:8765; mutations additionally require specified content type and X-LLMF-CSRF. An authenticated GET may omit Origin because same-origin browser fetch does so, but a present Origin must match exactly, and Sec-Fetch-Site is required as same-origin or none. Authentication is Bearer. The server sends no CORS allow header. Checks run in this fixed order and the first failure decides: (1) Host exactly 127.0.0.1:8765, else 403 ORIGIN_REJECTED reason HOST_MISMATCH; (2) OPTIONS, else continue, is 403 ORIGIN_REJECTED reason PREFLIGHT_REJECTED; (3) Origin: present and not exact is 403 ORIGIN_REJECTED reason ORIGIN_MISMATCH, absent on a mutation or session exchange is reason ORIGIN_MISSING; (4) GET only: Sec-Fetch-Site absent or not same-origin/none is 403 ORIGIN_REJECTED reason FETCH_SITE_REJECTED; (5) bearer token missing, unknown or revoked is 401 AUTH_REQUIRED, expired is 401 SESSION_EXPIRED; (6) mutation without a matching X-LLMF-CSRF is 403 CSRF_REJECTED; (7) content type 415 UNSUPPORTED_MEDIA_TYPE; (8) declared or streamed size 413 PAYLOAD_TOO_LARGE; only then is the body parsed. DELETE /api/v1/sessions/current revokes the calling session immediately. At most one unconsumed bootstrap secret exists; `pair`/connect replaces it. At most 32 unexpired sessions exist per instance; a further exchange returns 409 REGISTRY_LIMIT reason SESSION_LIMIT. Non-browser HTTP clients holding a session (for example qualification harnesses) set Sec-Fetch-Site: none; the CLI uses the control channel, not HTTP.

HTML responses set this exact Content-Security-Policy value:

    default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'self'; worker-src 'self'

They also set nosniff, no-referrer and same-origin CORP. Target assets contain no inline script/style or eval. Imported, model, error and log text enters the DOM via text nodes or one reviewed Trusted Types policy, never raw innerHTML.

## RUN-004 — Storage confinement and atomicity

The root is resolved once. Service rejects a symlink/reparse point, non-directory, WSL world-writable directory, or ACL writable by an unprivileged principal other than the current user. Windows ACL MAY retain SYSTEM and built-in Administrators for ordinary privileged maintenance; the companion makes no protection claim against a local administrator. It holds root/runtime/instance.lock; workers inherit a lease so replacement cannot start while one can write.

HTTP accepts registry IDs and uploads only: never paths, drive/UNC syntax, file URL, home expansion, glob, command, module, repository, revision or client URL. Layout is fixed:

    metadata.sqlite3
    objects/<sha256-prefix>/<sha256>/<safe-name>
    jobs/<job-id>/staging/
    runtime/control.json
    quarantine/<job-or-upload-id>/
    backups/

SQLite uses foreign keys, WAL and synchronous FULL. Files become artifacts only after streaming digest, flush, directory flush where supported, same-volume rename, then metadata commit. Names derive from digest. Existing digest bytes are reused only after length and hash match. Records use compare-and-swap versions; committed artifacts are immutable.

Archive members are rejected for empty, dot or dot-dot segments, leading slash, backslash, drive/UNC, NUL, duplicate normalized name, links, device/FIFO/socket, sparse/encrypted members or compression ratio above 100:1. Extraction remains in staging and enforces declared and actual limits. Uploads are never executed.

## RUN-005 — Transport limits and errors

JSON MUST be strict UTF-8 application/json, at most 1 MiB before decompression; content encoding, duplicate keys, non-finite numbers, trailing data and unknown properties are rejected. Dataset multipart allows at most three files, each at most 10 MiB and total at most 30 MiB. Parsed tiny/tokenizer text is at most 200,000 bytes; SFT text at most 20 MiB; datasets at most 100,000 records. Bundle staging accepts one .lfbundle, streamed, with archive upload at most 1 GiB and declared/actual expansion at most 2 GiB. Tiny prompt is at most 16,384 bytes and 512 new tokens. Chat is at most 64 messages, 8,192 bytes per message, 32,768 total and 128 new tokens.

All errors use error with code, optional stable reason_code, message, field_errors array of field_path and message, retryable and request_id. A path or query parameter that does not parse as its declared type or violates its bounds fails the schema stage with 400 VALIDATION_FAILED reason SCHEMA_INVALID, and its field_path is the parameter name without a leading slash (for example `after_cursor`), which cannot collide with a body pointer because body pointers begin with `/`. Boundary code determines HTTP handling; reason_code names the domain cause. Async job errors put that uppercase domain cause directly in job.error.code. Stable codes and statuses are INVALID_REQUEST and VALIDATION_FAILED 400; AUTH_REQUIRED and SESSION_EXPIRED 401; ORIGIN_REJECTED and CSRF_REJECTED 403; NOT_FOUND 404; METHOD_NOT_ALLOWED 405; IDEMPOTENCY_CONFLICT, STATE_CONFLICT and REGISTRY_LIMIT 409; PAYLOAD_TOO_LARGE and BACKUP_TOO_LARGE 413; UNSUPPORTED_MEDIA_TYPE 415; RANGE_NOT_SATISFIABLE 416; STORAGE_IN_USE 423; QUEUE_FULL 429; INTERNAL_ERROR 500; BACKEND_UNAVAILABLE, CAPABILITY_UNAVAILABLE, STORAGE_UNAVAILABLE, DISK_FULL and DEVICE_UNAVAILABLE 503. Learner messages never include paths, traceback or exception repr. Every reason_code and job error code, with its status and retryability, is listed in [contracts/error-vocabulary.json](contracts/error-vocabulary.json).

## RUN-006 — Registry and upload endpoints

OpenAPI paths are exhaustive. Lists return items and next_cursor, ordered created_at descending then ID descending, limit 1-100 and default 50. Opaque authenticated cursors bind order, filters, instance and schema. An empty `cursor` is the same as an absent one. A cursor that fails authentication, was issued for different filters, order, schema or service instance, or cannot be decoded returns 400 VALIDATION_FAILED reason SEMANTIC_INVALID with field_path `cursor` and changes no state.

POST /datasets accepts a JSON metadata part containing only name, record_format and optional provenance_note, plus one to three train/validation/test JSONL file parts. The client never supplies dataset/artifact IDs, digests, audit status or origin. The server validates multipart and schemas, independently recomputes final audit/provenance, creates the canonical dataset manifest, and commits all or nothing; it does not enqueue. Browser split/audit is preliminary display only and cannot make data eligible. Runtime enforces [data schemas](05-DATA-AND-ARTIFACTS.md), notably dataset-manifest.schema.json and data-audit.schema.json. POST /bundle-uploads stages an inert transport-safe bundle artifact but does not assert semantic validity or register contents. Registry list/detail routes exist for datasets, jobs, runs, models and checkpoints; artifact detail/content are RUN-014. Reads never mutate.

Learner-state routes are also binding. GET /progress returns the single progress-v2 document. PATCH /progress/modules/{module_id} requires expected_progress_revision, dimension, value and confirm_reset; revision mismatch is 409, and changing true to false requires confirm_reset true. Note routes list/get/create/update and use expected_revision on update. Conversation routes do the same, and turns are appended only by POST /conversations/{id}/commit-generation under expected revision; one conversation has one immutable base/adapter subject. A model change creates another conversation.

Note or conversation deletion is two-step. POST /{notes|conversations}/{id}/deletion-preview returns a CSPRNG preview_token, entity revision/digest, dependent IDs and a ten-minute expiry. DELETE submits that token, expected_revision and confirm true. Changed content/dependents, expiry or token reuse returns STATE_CONFLICT. Success tombstones the entity and returns 204; audit retains only IDs, times and content digest. No other delete route exists.

POST /diagnostic-receipts creates one immutable diagnostic artifact and returns its ArtifactDescriptor (201). It is authenticated/idempotent and uses the ordinary 1 MiB JSON body limit. tiny_head_validation accepts the full prescribed module-14 TinyTrainRequest with width 63 and heads 4; all other fields must pass request/registry validation. It reruns only pure configuration validation, must obtain VALIDATION_FAILED / CFG_HEAD_DIVISIBILITY at heads, and launches no worker or job. A valid configuration or a different error returns VALIDATION_FAILED without a receipt. failed_bundle_validation accepts a failed validate_bundle/import_bundle job ID whose immutable error is a bundle checksum/integrity failure; the service follows its request to the registered input artifact and copies exact error/request/input digests into the receipt. A nonmatching job returns STATE_CONFLICT. The receipt schema is diagnostic-receipt.schema.json. protected_registry_revision excludes diagnostic artifacts but includes jobs, datasets, runs, models, checkpoints, imports, notes, conversations and evidence; before/after must equal, job_count_delta is zero and diagnostic_write_count is exactly one. No host paths, secrets, traceback, submitted executable code or learner-supplied success assertion is retained. Failure to save a receipt changes no evidence state. UI offers Save diagnostic evidence after the named failure; an ordinary rejected request still creates no job. Diagnostic receipt creation does not mark the exercise verified.

Evidence routes list/get/create an unverified submission. POST /evidence/{id}/verify accepts one fixed verification_profile_id and expected evidence revision; the server runs only its named deterministic verifier over registered digest IDs. POST /evidence/{id}/assessments stores reviewer, rubric_version, decision and rationale. Verification never scores prose; assessment never claims an automated grade.

Progress import is explicit. POST /progress-imports/preview accepts one user-selected legacy-v1 or progress-v2 JSON backup up to 1 MiB, persists immutable source bytes, and returns source digest, format, database revision and per-category accepted/skipped/duplicate/conflict counts without mutation. POST /progress-imports/{preview_id}/apply requires preview digest, database revision, exactly one `resolutions` entry {handle, resolution: copy|skip} for every preview conflict of kind divergent and none for any other handle (otherwise 400 VALIDATION_FAILED reason SEMANTIC_INVALID at /resolutions), and confirm true; any changed input/database state invalidates it; success is one transaction. Preview expires after 30 minutes and cannot apply twice.

Capstone attempt creation freezes baseline_subject exactly as {kind: base_model, model_id}, candidate_subject exactly as {kind: adapter, checkpoint_id}, dataset ID/digest and evaluation profile. Creation returns the 256-bit base64url release_token exactly once. List/detail never returns the token; it returns attempt number, prior attempt, frozen subjects/data/config, token state, test exposure fresh_test or reused_test, evaluation job and created/consumed times. Consumption persists a dataset-digest exposure ledger even on failure/cancel; later same-dataset attempts are reused_test and never claim untouched test data. A replacement attempt requires reason first_attempt, prior_failed, prior_cancelled or new_experiment and follows DAT-013 restrictions. At most one attempt per manifest_sha256 may hold an available token; another create returns 409 STATE_CONFLICT reason ATTEMPT_ALREADY_OPEN. POST /capstone-attempts/{attempt_id}/abandon moves an unused attempt to token_state abandoned (for example after a lost token) without consuming or exposing test data; abandoning a non-available attempt returns 409 ATTEMPT_NOT_AVAILABLE. attempt_number is assigned per manifest_sha256 starting at 1. The idempotency store never retains the plaintext token: an idempotent replay of a create returns 409 STATE_CONFLICT reason SECRET_ALREADY_DELIVERED, and the learner abandons and recreates. The evaluate request artifact and its canonical digest replace release_token with token_sha256; the attempt stores that digest as evaluate_request_sha256 at consumption. Reasons follow semantic rule CAPSTONE_REASON_CHAIN (prior_attempt_id required for every reason except first_attempt; prior_failed after outcome failed; prior_cancelled after outcome interrupted; prior_abandoned after an abandoned attempt; new_experiment after a completed attempt with a different candidate checkpoint). The first completed attempt for a manifest_sha256 is the capstone's paired evaluation for CUR-012; later completed attempts are exploration, labelled reused_test, and cannot satisfy checklist item 6. An earlier attempt that consumed its token without completing does not prevent a later attempt from being the first completed one; that attempt's exposure is reused_test and it satisfies item 6.

Conversation generation does not mutate history. POST /conversations/{id}/commit-generation requires only expected_revision and generation_artifact_id from a completed chat_generate whose subject, serialized prior turns, pending user turn and revision match. It reads both user and assistant turns from the immutable artifact and appends both atomically. Failed/interrupted/cancelled or partial generation artifacts are rejected. POST /conversations/{id}/exports requires expected revision and sensitive-text confirmation and produces an inert JSONL dataset-candidate artifact; it is not a registered dataset and cannot train until separately uploaded through /datasets and audited.

Backup export POST /backup-exports emits format llm-foundations-learning-state-v1 containing progress and selected notes, evidence claims and conversations as one immutable UTF-8 JSON artifact of at most 8 MiB; selecting notes/conversations requires confirm_sensitive_text true. For each of notes, evidence and conversations: include_X false with X_ids present fails 400 VALIDATION_FAILED reason SEMANTIC_INVALID at /X_ids; include_X true with X_ids absent selects every live X at export time; include_X true with a nonempty X_ids selects exactly those, and an unknown or deleted ID fails 400 VALIDATION_FAILED reason REFERENCE_MISSING at /X_ids/<index>; include_X true with an empty X_ids fails SEMANTIC_INVALID at /X_ids. confirm_sensitive_text false while include_notes or include_conversations is true fails SEMANTIC_INVALID at /confirm_sensitive_text. The export preview lists exactly the selected items. Oversize returns BACKUP_TOO_LARGE 413 with no truncation or artifact and directs the learner to full .lfbundle export. Import preview streams the backup part with a 25,000,000-byte transport cap and then applies the detected format's cap: legacy v1 at its preserved 25,000,000-decimal-byte importBackup bound (the separate 1,000,000-byte bound applies only to recorded-run file selections), a progress-v2 document at 1 MiB, or this wrapper at 8 MiB. Ordinary JSON requests remain 1 MiB. Credentials, sessions and control data never enter it. Static intermediate sidecar uses key llm-foundations-intermediate-v1, retains the v1 key, caps 100 notes and preflights a 4 MiB quota as JSON.stringify UTF-16 code units times two so its wrapper remains exportable. Static mode cannot set artifact_verified or independent review; imported assertions remain imported_claim.

GET /preflight returns the latest startup receipt. The startup probe records Python 3.12 patch, interpreter label without host path, profile, device, storage display/writability, start/finish time and tests P00-RUN-001-PYTHON, P00-RUN-002-PROFILE, P00-RUN-003-STORAGE-WRITE, P00-RUN-004-STORAGE-READ-DIGEST, P00-RUN-005-STORAGE-DELETE and P00-RUN-006-BACKEND-CAPABILITIES. The storage test writes 4,096 CSPRNG bytes to service staging, flushes, reads and compares SHA-256, deletes and verifies absence. Receipt digest covers canonical JSON excluding receipt_sha256 and artifact ID. If storage is writable it registers the immutable receipt; otherwise artifact ID is null and status fail remains readable in memory. It never exposes interpreter path or probe filename.

Root limits are fixed: 50 GiB total companion-root bytes; 1 progress document with 24 module keys (P00, 00-20, E01 and E02); 1,000 live notes; 5,000 evidence records and 10 assessments each; 200 live conversations, 200 turns and 1 MiB text each; 100 capstone attempts; 20 active import/deletion previews; 1,000 datasets; 50,000 jobs; 20,000 runs; 512 models; 5,000 checkpoints; and 100,000 logical artifacts. A mutation that would exceed one returns REGISTRY_LIMIT 409 before bytes/rows change. Tombstoned notes/conversations do not count as live; append-only audit/job rows remain counted. When a nondeletable cap is reached, the learner must select a new storage root; v1 does not silently purge evidence. GET /runs accepts operation, job_state and backend filters; job_state joins the run's job. A terminal job that never created a run (for example DEVICE_UNAVAILABLE at start) is found through GET /jobs?state=failed or interrupted with run_id null.

## RUN-007 — Job creation and idempotency

POST /jobs accepts one discriminated request. Dataset/bundle upload, note/evidence/conversation/capstone/backup creation, progress/import apply, updates and deletes use the same idempotency record. Required Idempotency-Key is a lowercase UUID scoped to the service instance, HTTP method and path template with its resolved path parameters (control-channel requests use the same instance scope). For 24 hours the service stores key, canonical-request digest and the 2xx response; 4xx/5xx responses are never stored, so a corrected retry under the same key is evaluated fresh. Same key/body returns the stored response verbatim with header Idempotent-Replayed: true and no new event/job; changed body returns 409 IDEMPOTENCY_CONFLICT. Session expiry does not erase the mapping. For multipart uploads the idempotency digest is SHA-256 of canonical JSON {metadata_sha256, parts:[{name, size, sha256}] sorted by name}. Job exposes request.canonical_sha256, request.artifact_id and idempotency_key, and GET /jobs accepts request_sha256 and idempotency_key filters so a client that lost a response reconciles before any retry. Canonical request bytes are Python 3.12 json.dumps of the validated value with sort_keys true, separators literal comma and colon, ensure_ascii false and allow_nan false, UTF-8 encoded with no trailing LF and no Unicode normalization. Types validate first; finite numeric values and strings are preserved. Idempotency, preview and service request digests all use those bytes; bundle canonicalization is separate. The validated bytes are registered once as an immutable request artifact. Persisted job-record request is exactly {schema_id, canonical_sha256, artifact_id}; it contains no open request object. The worker verifies that artifact's digest and schema ID before closed-map dispatch.

References and type, capability, device, configuration, lineage and disk preflight precede insertion. Success transaction writes request, queued row and cursor-1 state event, then returns 202. A mutation is accepted only when OS free bytes are at least all active/queued outstanding reservations plus the new estimate plus a 1 GiB reserve AND current root bytes plus all outstanding reservations plus the new estimate are at most the 50 GiB root quota. Tokenizer estimate is 64 MiB. Tiny train estimate is max(512 MiB, C × (12 × P + 8 MiB) + 16 MiB), where P is computed unique parameters with tied aliases counted once and buffers excluded, and C = 1 + ceil(steps / eval_every) + 1 cancellation-checkpoint reserve; the 8 MiB per boundary covers attention-mask buffers plus bounded manifest/JSON, RNG and optimizer scalar data, and resume uses additional_steps with inherited eval_every. Adapter estimate is max(1 GiB, C × (12 × 460800 + 4 MiB) + 64 MiB), where C = 2 + ceil(updates / cadence), cadence is the preset's validation/save cadence (10 for smollm2-intents-lora-v1, 5 for smollm2-capstone-lora-v1), including initial and cancellation allowance. Evaluate/generate/context_preview/chat/retrieval estimate 256 MiB. Model_prepare estimate is 272,437,573 bytes plus 512 MiB. Dataset/bundle upload is Content-Length plus 64 MiB. Export is twice dependency-closure bytes plus 64 MiB; validate 64 MiB; import expanded bundle bytes plus 512 MiB. All arithmetic uses checked unsigned 64-bit integers. Unknown length, overflow, uncomputable P/C/closure or either failed inequality rejects before a row. A request whose own estimate exceeds 53,687,091,200 bytes can never be accepted and returns 400 VALIDATION_FAILED reason ESTIMATE_EXCEEDS_ROOT_QUOTA at the field that drives C (eval_every, steps/additional_steps or updates). Acceptance also reserves registry rows: a tiny or adapter training job reserves C checkpoint rows, 7 × C + 8 artifact rows, one run and one model row; every other job reserves 16 artifact rows and at most one run and one model row. Current rows plus all outstanding reservations plus the new reservation must not exceed any INT-007 registry count, otherwise 409 REGISTRY_LIMIT reason REGISTRY_COUNT_EXCEEDED before a row. Row reservations are released with the byte reservation; a job therefore cannot reach a registry cap mid-run, and if it does through a defect it fails INTERNAL_ERROR without partial registration. Reserve is not deliberately consumed. Later ENOSPC still fails the job.

## RUN-008 — Queue and state machine

One child may be starting, running or cancelling; eight additional jobs may be queued. FIFO is created_at then job_id. A ninth queued job returns 429 without a row. Session expiry does not expire jobs.

    queued -> starting -> running -> completed or failed
    queued, starting or running -> cancelling -> interrupted
    starting, running or cancelling -> interrupted on recovery, deadline or loss

Terminal states are immutable. Queued cancellation writes cancelling and interrupted events in one transaction, launches no worker and creates no checkpoint. Repeated cancel on cancelling/interrupted returns current job; completed/failed returns conflict. Starting precedes spawn; running requires worker validation acknowledgment. Completion requires valid typed result, committed artifacts and terminal event. Exit zero without protocol is WORKER_PROTOCOL_ERROR; nonzero is failed unless cancellation, timeout or recovery requires interrupted. Terminal reasons are the closed `TerminalReason` vocabulary: completed jobs use `completed`; interrupted jobs use `user_cancelled`, `timeout`, `exercise_timeout`, `service_restarted`, `service_shutdown`, `worker_lost` or `worker_ownership_unknown`; failed jobs set `terminal_reason` equal to `error.code`. An interrupted job carries `error` only for CHECKPOINT_WRITE_FAILED or WORKER_OWNERSHIP_UNKNOWN. A queued job has null phase, step and requested_final_step; a cancelling job has no error; an interrupted job that never started has no checkpoint boundary and reason `user_cancelled`. Cancellation in `starting` before the worker is spawned follows queued-cancel semantics; after spawn and before the running acknowledgment the owned worker is signalled and the job ends `interrupted`/`user_cancelled` within the 30-second grace. A clean service stop (SIGINT, SIGTERM, Windows console close, or `serve` shutdown) requests cancellation of the active job with reason `service_shutdown`, waits the 30-second grace, terminates only the owned worker container, records `interrupted`/`service_shutdown`, and leaves queued jobs queued; an unclean stop is resolved at recovery as `service_restarted`.

## RUN-009 — Budgets, deterministic cancellation and process ownership

The 60-minute compute deadline starts at starting and covers loading, execution and checkpointing. At started_at + 3,600 seconds the service requests cancellation with reason timeout. After any cancellation request (learner, deadline, shutdown) the worker has exactly 30 seconds to return interrupted; the grace is never shortened by a later deadline, and the first request's reason is kept. Then the service terminates only its owned process container and records interrupted with the latest committed checkpoint, if any; a worker that exits without protocol during that grace is recorded with reason worker_lost.

Tiny-v2 and adapter training poll cancellation before and after every optimizer update. They stop new updates, atomically write a resumable checkpoint for the last completed update, emit checkpoint_committed and return interrupted. Checkpoint-write failure leaves interrupted with prior or null checkpoint plus CHECKPOINT_WRITE_FAILED. Other operations stop at the next chunk, record or token boundary; partial output is never complete.

The prescribed module-14 request has exercise_profile_id tiny-v2-diagnosis-v1 and curriculum_hold_after_step exactly 25. ## RUN-017 — Truthful fault records

Boundary validation, unavailable capability, full queue and disk preflight create no job. Post-accept failure creates exactly one terminal state/event. Failed is operation error; interrupted is cancellation, deadline or process/service loss. Neither is completion.

On ENOSPC/quota, stop writes, roll back current metadata, mark failed DISK_FULL if commit remains possible, preserve prior artifacts. If SQLite cannot commit, recovery converts nonterminal to interrupted; it does not invent a result. Scheduling pauses while storage_writable false.

Out-of-order step, nonfinite metric, hash mismatch, step inconsistency, unknown result field or discriminator mismatch is WORKER_PROTOCOL_ERROR. Uncommitted output is quarantined, never exposed as run. This preserves lab lines 171-180 completed/interrupted/failed distinction.
