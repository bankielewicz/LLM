# Local companion runtime and API

Status: normative implementation specification. This file defines the release target; it does not claim implementation or qualification. It is subordinate to [00-DECISIONS.md](00-DECISIONS.md). The machine contract is [contracts/openapi.json](contracts/openapi.json); acceptance cases are [trace/RUN.json](trace/RUN.json).

The preserved lab already separates training, resume, generation, evaluation, tokenization and inspection; refuses an existing output directory; caps training text; atomically replaces checkpoints; and records failure or interruption distinctly ([course/labs/lab.py](../../../course/labs/lab.py), lines 79-180 and 183-248). The static reader currently loads content and recorded runs in-browser and says it does not run Python ([dist/app.js](../../../dist/app.js), lines 10 and 60). These are baselines, not claims about the target companion.

KiB, MiB and GiB mean powers of 1024. UTF-8 byte length uses strict encoding. Timestamps are RFC 3339 UTC with Z and milliseconds. IDs are lowercase UUIDs generated by the companion. Digests are lowercase SHA-256 hex.

## RUN-001 — Modes, launch and discovery

The hosted/static reader MUST make no companion request. It MUST label simulations and recorded data and disable every live action with “Start the local companion to run this operation.”

The companion MUST bind only 127.0.0.1:8765, serving reader and /api/v1 on that origin. It MUST NOT bind 0.0.0.0, IPv6, localhost, LAN or public interfaces. Package/import names are llm-foundations-companion and llm_foundations_companion. Entrypoints are:

    python -m llm_foundations_companion serve --storage <root> [--profile win-cpu|wsl-cpu|wsl-cuda]
    python -m llm_foundations_companion connect --storage <root>
    python -m llm_foundations_companion status --storage <root>
    python -m llm_foundations_companion request --storage <root> --file <request.json>
    python -m llm_foundations_companion cancel --storage <root> --job-id <uuid>
    python -m llm_foundations_companion events --storage <root> --job-id <uuid> --after <cursor>

Default root is ~/.llm-foundations. Serve prints its resolved root and fails if its lock or port is occupied; it never selects another port. On native Windows, only win-cpu is valid; on WSL, wsl-cpu and wsl-cuda are valid. Omitting --profile selects the OS CPU profile (win-cpu or wsl-cpu) and never selects CUDA. wsl-cuda requires the explicit flag and a passing CUDA preflight. Invalid OS/profile pairs fail before the instance lock is published. The selected profile is immutable for that service instance; changing it requires a clean service stop, resolution of every nonterminal job under RUN-010, and relaunch against the same owned root. Applied operations derive device from the selected profile, never fall back to another device, and accept no HTTP profile/device mutation. Status, runtime and the P00 receipt record the selected profile and device. Connect issues pairing without stopping work. CLI requests use the same validators and limits as HTTP.

Unauthenticated GET /healthz returns only status and api_version. At startup the service runs the fixed P00 preflight in RUN-006. Authenticated GET /api/v1/runtime returns mode, api_version, runtime_version, instance_id, profile, device, storage_root_display, storage_writable, server_time, exact limits, and capability records with available, reason_code and message. It MUST NOT disclose credentials, internal paths, environment, package indexes or hostnames.

## RUN-002 — Package and process boundary

The package MUST preserve this responsibility direction:

    llm_foundations_companion/
      __main__.py, cli.py                 fixed commands/local-control client
      api.py, auth.py, limits.py          HTTP, pairing, boundary validation
      registry.py, database.py            registry and SQLite transactions
      scheduler.py, events.py             FIFO scheduler and event log
      worker_main.py, worker_protocol.py   fixed worker and IPC
      operations/                          allowlisted operation modules
      legacy_adapter.py                    preserved-lab compatibility
      static/, migrations/

The service process MUST NOT import Torch, Transformers or PEFT or compute with models. Each job runs in a new child with fixed argv: python -I -m llm_foundations_companion.worker_main --job-id UUID --instance-id UUID. Request data cannot change executable, module, working directory, environment names or argv shape.

A canonical request crosses an inherited pipe. Dispatch is a closed map containing tokenizer_train, tiny_train, tiny_resume, evaluate, generate, model_prepare, adapter_train, adapter_resume, context_preview, chat_generate, retrieval_build, retrieval_query, export_bundle, validate_bundle and import_bundle. Workers MUST NOT use a shell, eval, exec, dynamic imports/plugins, notebooks, uploaded code, pickle from uploads or trust_remote_code. Applied weights use safetensors. Legacy checkpoints are opened only by the fixed adapter using Torch weights_only=True, matching lab lines 26-33.

Worker environment is an allowlist for the qualified interpreter/runtime, UTF-8, profile Torch controls, job/instance IDs and staging path. Proxy, Python-path, shell-startup, credential and arbitrary parent variables are absent. Stdout and stderr are each capped at 1 MiB; truncation emits a warning. Logs are untrusted downloadable artifacts.

## RUN-003 — Pairing, sessions and browser security

Each serve generates a CSPRNG instance_id, 256-bit control secret and bootstrap secret. Root/runtime/control.json is current-user-only: mode 0600 on WSL and user-only ACL on Windows. Connect verifies instance and PID through the private control channel and prints http://127.0.0.1:8765/#/connect/SECRET without restart. The internal control endpoint requires the file secret and accepts no browser Origin.

Bootstrap expires in 120 seconds and is single-use. Its URL fragment never reaches HTTP, Referer or logs. JS removes it with history.replaceState, then sends it to POST /api/v1/sessions. Success invalidates it and returns independent 256-bit access_token and csrf_token, instance_id, idle_expires_at and absolute_expires_at. Invalid, expired and reused secrets share 401 AUTH_REQUIRED.

Credentials live only in sessionStorage scoped by instance, permitting same-tab reload. They MUST NOT enter localStorage, IndexedDB, URL, progress, notebook, export, log or crash report. Disconnect or expiry clears them. Sessions expire after two idle hours and 12 absolute hours; stream heartbeats do not refresh idle time. Restart invalidates sessions.

All /api requests require exact Host 127.0.0.1:8765. Session exchange and mutations require exact Origin http://127.0.0.1:8765; mutations additionally require specified content type and X-LLMF-CSRF. An authenticated GET may omit Origin because same-origin browser fetch does so, but a present Origin must match exactly, and Sec-Fetch-Site is required as same-origin or none. Authentication is Bearer. The server sends no CORS allow header and rejects preflight. Checks precede body parsing. CLI GET sets Sec-Fetch-Site: none.

HTML responses set this exact Content-Security-Policy value:

    default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'self'; worker-src 'self'

They also set nosniff, no-referrer and same-origin CORP. Target assets contain no inline script/style or eval. Imported, model, error and log text enters the DOM via text nodes or one reviewed Trusted Types policy, never raw innerHTML.

## RUN-004 — Storage confinement and atomicity

The root is resolved once. Service rejects a symlink/reparse point, non-directory, WSL world-writable directory, or ACL writable by an unprivileged principal other than the current user. Windows ACL MAY retain SYSTEM and built-in Administrators for ordinary privileged maintenance; the companion makes no protection claim against a local administrator. It holds root/runtime/instance.lock; workers inherit a lease so replacement cannot start while one can write.

HTTP accepts registry IDs and uploads only: never paths, drive/UNC syntax, file URL, home expansion, glob, command, module, repository, revision or client URL. Layout is fixed:

    metadata.sqlite3
    objects/<sha256-prefix>/<sha256>/<safe-name>
    jobs/<job-id>/staging/
    runtime/control.json
    quarantine/<job-or-upload-id>/

SQLite uses foreign keys, WAL and synchronous FULL. Files become artifacts only after streaming digest, flush, directory flush where supported, same-volume rename, then metadata commit. Names derive from digest. Existing digest bytes are reused only after length and hash match. Records use compare-and-swap versions; committed artifacts are immutable.

Archive members are rejected for empty, dot or dot-dot segments, leading slash, backslash, drive/UNC, NUL, duplicate normalized name, links, device/FIFO/socket, sparse/encrypted members or compression ratio above 100:1. Extraction remains in staging and enforces declared and actual limits. Uploads are never executed.

## RUN-005 — Transport limits and errors

JSON MUST be strict UTF-8 application/json, at most 1 MiB before decompression; content encoding, duplicate keys, non-finite numbers, trailing data and unknown properties are rejected. Dataset multipart allows at most three files, each at most 10 MiB and total at most 30 MiB. Parsed tiny/tokenizer text is at most 200,000 bytes; SFT text at most 20 MiB; datasets at most 100,000 records. Bundle staging accepts one .lfbundle, streamed, with archive upload at most 1 GiB and declared/actual expansion at most 2 GiB. Tiny prompt is at most 16,384 bytes and 512 new tokens. Chat is at most 64 messages, 8,192 bytes per message, 32,768 total and 128 new tokens.

All errors use error with code, optional stable reason_code, message, field_errors array of field_path and message, retryable and request_id. Boundary code determines HTTP handling; reason_code names the domain cause. Async job errors put that uppercase domain cause directly in job.error.code. Stable codes and statuses are INVALID_REQUEST and VALIDATION_FAILED 400; AUTH_REQUIRED and SESSION_EXPIRED 401; ORIGIN_REJECTED and CSRF_REJECTED 403; NOT_FOUND 404; METHOD_NOT_ALLOWED 405; IDEMPOTENCY_CONFLICT, STATE_CONFLICT and REGISTRY_LIMIT 409; PAYLOAD_TOO_LARGE and BACKUP_TOO_LARGE 413; UNSUPPORTED_MEDIA_TYPE 415; RANGE_NOT_SATISFIABLE 416; STORAGE_IN_USE 423; QUEUE_FULL 429; INTERNAL_ERROR 500; BACKEND_UNAVAILABLE, CAPABILITY_UNAVAILABLE, STORAGE_UNAVAILABLE, DISK_FULL and DEVICE_UNAVAILABLE 503. Learner messages never include paths, traceback or exception repr.

## RUN-006 — Registry and upload endpoints

OpenAPI paths are exhaustive. Lists return items and next_cursor, ordered created_at descending then ID descending, limit 1-100 and default 50. Opaque authenticated cursors bind order, filters, instance and schema; changed or invalid cursors fail.

POST /datasets accepts a JSON metadata part containing only name, record_format and optional provenance_note, plus one to three train/validation/test JSONL file parts. The client never supplies dataset/artifact IDs, digests, audit status or origin. The server validates multipart and schemas, independently recomputes final audit/provenance, creates the canonical dataset manifest, and commits all or nothing; it does not enqueue. Browser split/audit is preliminary display only and cannot make data eligible. Runtime enforces [data schemas](05-DATA-AND-ARTIFACTS.md), notably dataset-manifest.schema.json and data-audit.schema.json. POST /bundle-uploads stages an inert transport-safe bundle artifact but does not assert semantic validity or register contents. Registry list/detail routes exist for datasets, jobs, runs, models and checkpoints; artifact detail/content are RUN-014. Reads never mutate.

Learner-state routes are also binding. GET /progress returns the single progress-v2 document. PATCH /progress/modules/{module_id} requires expected_progress_revision, dimension, value and confirm_reset; revision mismatch is 409, and changing true to false requires confirm_reset true. Note routes list/get/create/update and use expected_revision on update. Conversation routes do the same and append turns only under expected revision; one conversation has one immutable base/adapter subject. A model change creates another conversation.

Note or conversation deletion is two-step. POST /{notes|conversations}/{id}/deletion-preview returns a CSPRNG preview_token, entity revision/digest, dependent IDs and a ten-minute expiry. DELETE submits that token, expected_revision and confirm true. Changed content/dependents, expiry or token reuse returns STATE_CONFLICT. Success tombstones the entity and returns 204; audit retains only IDs, times and content digest. No other delete route exists.

Evidence routes list/get/create an unverified submission. POST /evidence/{id}/verify accepts one fixed verification_profile_id and expected evidence revision; the server runs only its named deterministic verifier over registered digest IDs. POST /evidence/{id}/assessments stores reviewer, rubric_version, decision and rationale. Verification never scores prose; assessment never claims an automated grade.

Progress import is explicit. POST /progress-imports/preview accepts one user-selected legacy-v1 or progress-v2 JSON backup up to 1 MiB, persists immutable source bytes, and returns source digest, format, database revision and per-category accepted/skipped/duplicate/conflict counts without mutation. POST /progress-imports/{preview_id}/apply requires preview digest, database revision and confirm true; any changed input/database state invalidates it; success is one transaction. Preview expires after 30 minutes and cannot apply twice.

Capstone attempt creation freezes baseline_subject exactly as {kind: base_model, model_id}, candidate_subject exactly as {kind: adapter, checkpoint_id}, dataset ID/digest and evaluation profile. Creation returns the 256-bit base64url release_token exactly once. List/detail never returns the token; it returns attempt number, prior attempt, frozen subjects/data/config, token state, test exposure fresh_test or reused_test, evaluation job and created/consumed times. Consumption persists a dataset-digest exposure ledger even on failure/cancel; later same-dataset attempts are reused_test and never claim untouched test data. A replacement attempt requires reason first_attempt, prior_failed, prior_cancelled or new_experiment and follows DAT-013 restrictions.

Conversation generation does not mutate history. POST /conversations/{id}/commit-generation requires only expected_revision and generation_artifact_id from a completed chat_generate whose subject, serialized prior turns, pending user turn and revision match. It reads both user and assistant turns from the immutable artifact and appends both atomically. Failed/interrupted/cancelled or partial generation artifacts are rejected. POST /conversations/{id}/exports requires expected revision and sensitive-text confirmation and produces an inert JSONL dataset-candidate artifact; it is not a registered dataset and cannot train until separately uploaded through /datasets and audited.

Backup export POST /backup-exports emits format llm-foundations-learning-state-v1 containing progress and selected notes, evidence claims and conversations as one immutable UTF-8 JSON artifact of at most 8 MiB; selecting notes/conversations requires confirm_sensitive_text true. Oversize returns BACKUP_TOO_LARGE 413 with no truncation or artifact and directs the learner to full .lfbundle export. Import preview accepts legacy v1 at its existing 1,000,000-byte UI bound, a progress-v2 document at 1 MiB, or this wrapper at 8 MiB. Ordinary JSON requests remain 1 MiB. Credentials, sessions and control data never enter it. Static intermediate sidecar uses key llm-foundations-intermediate-v1, retains the v1 key, caps 100 notes and preflights a 4 MiB quota as JSON.stringify UTF-16 code units times two so its wrapper remains exportable. Static mode cannot set artifact_verified or independent review; imported assertions remain imported_claim.

GET /preflight returns the latest startup receipt. The startup probe records Python 3.12 patch, interpreter label without host path, profile, device, storage display/writability, start/finish time and tests P00-RUN-001-PYTHON, P00-RUN-002-PROFILE, P00-RUN-003-STORAGE-WRITE, P00-RUN-004-STORAGE-READ-DIGEST, P00-RUN-005-STORAGE-DELETE and P00-RUN-006-BACKEND-CAPABILITIES. The storage test writes 4,096 CSPRNG bytes to service staging, flushes, reads and compares SHA-256, deletes and verifies absence. Receipt digest covers canonical JSON excluding receipt_sha256 and artifact ID. If storage is writable it registers the immutable receipt; otherwise artifact ID is null and status fail remains readable in memory. It never exposes interpreter path or probe filename.

Root limits are fixed: 50 GiB total companion-root bytes; 1 progress document with 24 module keys (P00, 00-20, E01 and E02); 1,000 live notes; 5,000 evidence records and 10 assessments each; 200 live conversations, 200 turns and 1 MiB text each; 100 capstone attempts; 20 active import/deletion previews; 1,000 datasets; 50,000 jobs; 20,000 runs; 512 models; 5,000 checkpoints; and 100,000 logical artifacts. A mutation that would exceed one returns REGISTRY_LIMIT 409 before bytes/rows change. Tombstoned notes/conversations do not count as live; append-only audit/job rows remain counted. When a nondeletable cap is reached, the learner must select a new storage root; v1 does not silently purge evidence.

## RUN-007 — Job creation and idempotency

POST /jobs accepts one discriminated request. Dataset/bundle upload, note/evidence/conversation/capstone/backup creation, progress/import apply, updates and deletes use the same idempotency record. Required Idempotency-Key is a lowercase UUID scoped to session, method and path. For 24 hours the service stores key, canonical-request digest and response. Same key/body returns the original response without event/job; changed body returns conflict. Session expiry does not erase mapping. Canonical request bytes are Python 3.12 json.dumps of the validated value with sort_keys true, separators literal comma and colon, ensure_ascii false and allow_nan false, UTF-8 encoded with no trailing LF and no Unicode normalization. Types validate first; finite numeric values and strings are preserved. Idempotency, preview and service request digests all use those bytes; bundle canonicalization is separate. The validated bytes are registered once as an immutable request artifact. Persisted job-record request is exactly {schema_id, canonical_sha256, artifact_id}; it contains no open request object. The worker verifies that artifact's digest and schema ID before closed-map dispatch.

References and type, capability, device, configuration, lineage and disk preflight precede insertion. Success transaction writes request, queued row and cursor-1 state event, then returns 202. A mutation is accepted only when OS free bytes are at least all active/queued outstanding reservations plus the new estimate plus a 1 GiB reserve AND current root bytes plus all outstanding reservations plus the new estimate are at most the 50 GiB root quota. Tokenizer estimate is 64 MiB. Tiny train estimate is max(512 MiB, C × (12 × P + 8 MiB) + 16 MiB), where P is computed unique parameters with tied aliases counted once and buffers excluded, and C = 1 + ceil(steps / eval_every) + 1 cancellation-checkpoint reserve; the 8 MiB per boundary covers attention-mask buffers plus bounded manifest/JSON, RNG and optimizer scalar data, and resume uses additional_steps with inherited eval_every. Adapter estimate is max(1 GiB, C × (12 × 460800 + 4 MiB) + 64 MiB), where C = 2 + ceil(updates / 10), including initial and cancellation allowance. Evaluate/generate/context_preview/chat/retrieval estimate 256 MiB. Model_prepare estimate is 272,437,573 bytes plus 512 MiB. Dataset/bundle upload is Content-Length plus 64 MiB. Export is twice dependency-closure bytes plus 64 MiB; validate 64 MiB; import expanded bundle bytes plus 512 MiB. All arithmetic uses checked unsigned 64-bit integers. Unknown length, overflow, uncomputable P/C/closure or either failed inequality rejects before a row. Reserve is not deliberately consumed. Later ENOSPC still fails the job.

## RUN-008 — Queue and state machine

One child may be starting, running or cancelling; eight additional jobs may be queued. FIFO is created_at then job_id. A ninth queued job returns 429 without a row. Session expiry does not expire jobs.

    queued -> starting -> running -> completed or failed
    queued, starting or running -> cancelling -> interrupted
    starting, running or cancelling -> interrupted on recovery, deadline or loss

Terminal states are immutable. Queued cancellation writes cancelling and interrupted events in one transaction, launches no worker and creates no checkpoint. Repeated cancel on cancelling/interrupted returns current job; completed/failed returns conflict. Starting precedes spawn; running requires worker validation acknowledgment. Completion requires valid typed result, committed artifacts and terminal event. Exit zero without protocol is WORKER_PROTOCOL_ERROR; nonzero is failed unless cancellation, timeout or recovery requires interrupted.

## RUN-009 — Budgets, deterministic cancellation and process ownership

The 60-minute compute deadline starts at starting and includes loading, execution, checkpoint and cancellation. Deadline requests cancellation with reason timeout. Worker has 30 seconds to return interrupted; then service terminates only its owned process container and records interrupted with the latest committed checkpoint, if any.

Tiny-v2 and adapter training poll cancellation before and after every optimizer update. They stop new updates, atomically write a resumable checkpoint for the last completed update, emit checkpoint_committed and return interrupted. Checkpoint-write failure leaves interrupted with prior or null checkpoint plus CHECKPOINT_WRITE_FAILED. Other operations stop at the next chunk, record or token boundary; partial output is never complete.

The prescribed module-14 request has exercise_profile_id tiny-v2-diagnosis-v1 and curriculum_hold_after_step exactly 25. Both fields MUST appear together and are rejected for every other profile/value. After committing evaluation/checkpoint at step 25, the worker emits phase_changed with phase cancellable_hold and waits up to 10 minutes. Cancellation returns interrupted at step 25 with that checkpoint. If no cancellation arrives, it atomically writes an interrupted result with reason exercise_timeout at step 25. It never continues updates. The UI does not expose an editable hold control.

Windows uses a per-worker Job Object with kill-on-close and retained handle. WSL uses a new process group plus parent-death signal. The service never scans/kills by name or accepts a PID. It signals only a retained handle/group whose 256-bit spawn nonce matches the job. If ownership is unprovable it records WORKER_OWNERSHIP_UNKNOWN, refuses a replacement worker for that root and does not kill the process.

Tiny requests cap updates 2,000, batch 64, context 512, width 512, heads 16, layers 12 and computed parameters 10,000,000; width divides by heads. Applied jobs use only [the pinned applied contract](06-APPLIED-MODELS.md). CUDA runs only on wsl-cuda with request device cuda and successful preflight. There is no CPU fallback.


## RUN-010 — Crash recovery and reconnect

Recovery precedes sessions and scheduling. It verifies schema, lock, artifact references and job/event consistency. Queued jobs remain FIFO. Starting, running or cancelling jobs become interrupted with reason service_restarted. Service MUST NOT infer completion from files, auto-resume or relabel checkpoints. Valid committed artifacts remain; unreferenced staging moves to quarantine.

All browser sessions are invalid after restart. On network loss/reload, UI shows “Connection lost · job state unknown” for each cached nonterminal job and MUST NOT advance or infer failure. After pairing it gets job snapshot then replays after its last cursor. Missing job shows “Job not found in this companion storage” and is not recreated.

Database integrity failure, unsupported future migration, unavailable root or bad registered digest starts read-only recovery mode. Health and pairing work; runtime reports storage_writable false; safe reads work; mutations return STORAGE_UNAVAILABLE. The service never automatically deletes or rewrites evidence.

## RUN-011 — Events, replay and fetch-stream SSE

Each job cursor begins at 1 and increases. State transactions insert their event. Closed event types are state_changed, phase_changed, progress, metric, warning, checkpoint_committed and terminal. Each has job_id, cursor, event_type, occurred_at and typed payload. Metrics identify phase, step, split and values; training payload has step and nullable requested_final_step; terminal has state, reason_code and checkpoint boundary.

GET /jobs/{id}/events returns cursor-greater-than after_cursor ascending, default 100/max 500, next_after_cursor and has_more. Event stream uses authenticated fetch, not EventSource, because Authorization is required. It emits text/event-stream with id=cursor, event=type, full event JSON data; 15-second comment heartbeats; closes after five minutes, 500 data events or terminal. Reconnect uses last fully parsed cursor; duplicate cursor is ignored.

Every job retains all of its at most 4,096 events. Cardinality is bounded before insertion: at most 2,001 metric events and 2,001 checkpoint events, one of each per initial/evaluation boundary; six state events; 32 phase events; 32 warning events; 16 persisted progress milestones; and one terminal event. Further warnings are counted in warning_suppressed_count and a diagnostic artifact, not emitted; progress replaces the current milestone before insertion rather than adding one. A worker request whose declared schedule could exceed 2,001 evaluation boundaries is rejected. If any producer would exceed the total cap, the service records WORKER_PROTOCOL_ERROR as the final available event and stops the worker. Heartbeats are not events and have no cursor. Because v1 never prunes an event, oldest_cursor is always 1 and after_cursor from 0 through last_cursor is replayable.
